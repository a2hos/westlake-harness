# Cross-APK reference-frequency pilot (static only)

Target: OpenHarmony 7.0.0.39, AOSP 16.0.0_r4, ARM64, App-side Bionic. This pilot uses the upstream harness's per-APK gap-map principle of collecting exact DEX members and ELF imports, but it performs **no provider subtraction or runtime gap verdict**. The upstream method distinguishes APK references from source, probe, and observed-on-device evidence; that distinction is retained here.

`freeze_inputs.py` pins exactly 78 distinct package inventories to the currently root-accepted static receipts. It excludes the incomplete Signal and OpenKeychain inventories, failed/partial runs, synthetic fixtures, duplicate Vivaldi v2, and superseded a4 v1. The later accepted VLC inventory replaces the prior VLC timeout. Batch12 v3's 14 individually accepted true ELF records are reconstructed from its root-accepted aggregate; three ZIP payloads named `.so` are not counted as ELF. Each input path is SHA-256 pinned in `INPUT-MANIFEST.json` (`b639dac4b3f49e7e1091399890230337e8bd6ae214fc856d7ba4dbf7ba9f402f`). This is a selection of accepted static receipts, not a fresh APK scan.

Actual local pilot: `aggregate.py` exit 0; `PILOT-OUTPUT.json` SHA-256 `f5632ac647489d7a60c7f66b2bd0cae71cc9e6f17d629903d44cbce234e4b4cd`. Input covers 78 packages, 197 DEX entries, and 365 true AArch64 ELF entries. Each method/symbol counts each package at most once, irrespective of DEX call-site count or number of libraries. `Context.getSystemService(String)` is declared in 77 packages; `__system_property_get` is undefined in native libraries of 49 packages. These are reference frequencies only. ARM32 imports are excluded from the ARM64 ranking. All reachability, provider implementation, runtime-gap and cold-start-blocker fields are explicitly `UNKNOWN`.

One shared candidate to verify after the first native target is built: the Bionic property-read boundary represented by `__system_property_get`. Check its symbol export and Android property-area behavior with a minimal probe in the HelloWorld Bionic process, then compare a truly cold APK load/readback; a passing symbol lookup alone is insufficient. The 49-package rank gives this a potentially broad payoff, but does **not** establish that any of these apps call the symbol during startup or that the current adapter lacks it. Do not create a fix or mark APKs unblocked from this scan alone.

The pilot does not resolve Java members against the exact AOSP16 boot jars, subtract exports from the target Bionic/OH binaries, prove dynamic loading, account for dynamically loaded code, or observe device execution. It does not change canonical APK startup or 89-tool counts.
