# AIMP Android 4.31.1747: official raw and host static candidate

**Decision for independent root review:** admit the exact unmodified raw APK and its complete four-phase native-host static inventory as candidates. Do not change authoritative counts yet. Blackbox qualification is a separate candidate; no installation, loader selection, cold start, screen, or device behavior is proved.

The [publisher's Android download page](https://aimp.ru/?do=download&os=android) names stable `4.31.1747`, ARM64 / ARMv7 / x86-64, and SHA-256 `2d70fb1cb519104826d825d2060289ad77fbd75b5b68c00ff93631ffafa06a46`; its `id=13` APK link remains on `aimp.ru`. The fetched 22,321,372-byte APK matches that publisher hash exactly. Independent host `aapt2` and `apksigner` commands returned rc=0: package `com.aimp.player`, versionCode `1747`, manifest versionName `v4.31.1747 (10.09.2026)`, signer certificate SHA-256 `b05cf2cf7252241b39f7ec1fc42b6ce0eaf9f7715c0b0144a7f836a3725e2a4d`. The page label is a shortened version of the manifest name; this is recorded explicitly. `targetSdk=37` is a compatibility risk against AOSP16 API36, not evidence of install failure.

ZIP has 1,442 entries, one manifest, no duplicate names or bad CRC. The four phases all returned rc=0 with the same APK SHA before and after: metadata as above, one root DEX, and 19 true `ELF64 AArch64` libraries with 19/19 `readelf_ok` and ABI matches. Candidate outputs and raw tool streams are hashed in `HANDOFF.json`. The existing upstream registry and G339 frozen 105-package accepted set have no `com.aimp.player`; a scoped search of current project evidence found no earlier AIMP admission.

For blackbox eligibility, [Google Play's AIMP listing](https://play.google.com/store/apps/details?id=com.aimp.player) shows the same package and 50M+ downloads, while the publisher's [Android EULA](https://aimp.ru/?do=eula&os=android) distributes freeware binaries and third-party notices. A [publisher blog statement](https://aimp.ru/blogs/?language=en&p=1157) said source would be opened only if the project closed; this older statement requires a current root check before blackbox qualification. Partial third-party library notices do not make the application source publicly available. No public full Android application source was identified in this bounded review.

The initial `peer-apk-portfolio-aimp-official-v1` page preflight failed rc=1 because it expected HTML `&amp;` where the publisher served literal `&`; it did not fetch an APK. The v2 raw acquisition returned rc=0. Its first signature parser run returned rc=2 because it demanded the abbreviated page version as the manifest versionName; the original `VERIFY.json` remains as failure evidence. `verify_v2.py` compares the actual signed manifest identity and returned rc=0. The static generation returned rc=0. All work used the project's native host, local staging, no containers, devices, or BridgeAOSPV16; control and count files were not edited.
