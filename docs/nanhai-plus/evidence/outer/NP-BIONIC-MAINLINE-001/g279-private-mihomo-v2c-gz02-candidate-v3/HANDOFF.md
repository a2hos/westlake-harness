# G279 v2c v3 — bounded failure diagnostics, code only

v2's frozen terminal (`88010674…`) reported rc 2, `InstanceFailure`, one local SSH `Popen` callback, no persisted local negative result or log metadata, and clean process/private-directory removal. The independent postrun peer (`3010164a…`) and root NO_GO (`9409e940…`) accept only failure and cleanup. TCP, banner, host key, public-key authentication, UID and positive route remain **UNKNOWN** for that run. Its nonce is consumed and is never replayed.

This new generation preserves that exact failure chain and adds fixed, no-secret failure diagnostics before private raw logs are deleted. The instance records its last completed local stage and a category from a closed enum. The SSH child contributes only return code (or null), timeout flag, stdout/stderr byte counts, and a fixed `last_ssh_stage` enum. A strict parser recognizes safe banner, pinned-key, public-key-authentication and numeric-UID lines internally to select that enum; it never exports raw SSH output, exception text, node names or credentials on failure. A line observed is **not** an independently retained authentication proof. A missing line leaves transport and cause unknown; child launch alone never proves TCP or banner. When an exact SSH identity proof succeeds, the v2 safe replayable witness remains available in the success result.

If later steps fail, `InstanceFailure` carries the already proven local TEST-NET-3 REJECT result and bounded diagnostic into the terminal. On clean stop, any positive-route witness is exported only on a complete success path. If cleanup or listener ownership is unproven, the private directory is retained and success is denied. `validate_instance_diagnostic` rejects extra fields before terminal publication. The actual failed v2 substage cannot be reconstructed from the deleted v2 streams, and v3 does not pretend otherwise.

The no-credential fixture receipt covers fake SSH nonzero exit, timeout, banner/key/auth/UID enum observations, a fake child process callback, malformed diagnostics, and the v2 route/SSH witness negative cases. No new Mihomo, real SSH, selected node, gz02 connection, device, container, graph or HK01 action ran. The v2 loopback-only fake-node format receipt is referenced unchanged. This v3 directory has no peer GO, root release, START or TERMINAL. A separate independent code review is required before any new one-shot release.

EVO49's preflight-before-START split is not implemented here. It is an efficiency improvement separate from the failure diagnostic repair.
