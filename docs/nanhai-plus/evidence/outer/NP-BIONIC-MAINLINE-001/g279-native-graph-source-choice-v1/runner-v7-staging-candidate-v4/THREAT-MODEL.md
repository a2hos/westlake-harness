# G279 v7 staging v4 boundary

This candidate performs one project-only write attempt to gz02. Its only remote write names are `control/g279-native-graph-v7-stage-v4.lease` and `control/nanhai_plus_native_graph_v7.py` under the `NANHAI_GZ02_NATIVE_PROJECT_ROOT` from the current `local_env.md`. No source, OUT/TMP, graph, container, device, or Bridge path is written. The staged runner is data: this transport never executes it.

The local `UNKNOWN.json` is created exclusively and fsynced before SSH. The remote lease is then created exclusively and fsynced before the runner path. A second local call or a second remote program fails closed. A timeout, malformed response, lease mismatch, parent-path drift, interrupted write, or missing terminal receipt leaves `UNKNOWN` and any remote files in place. There is no automatic unlink. The only recovery is an independent read-only inspection of the lease, final file, project/control owner and modes, followed by a separately reviewed new decision. Never rerun this generation after an ambiguous outcome.

The path walk uses directory fds and `O_NOFOLLOW`; project and control must be owned by the non-root SSH UID and deny group/other writes. It compares the named parent chain before and after mutation and reads back the lease and final file by fd, including SHA, bytes, mode, UID and inode. This proves a bounded observation for a cooperative single-owner project directory. It does not make a same-UID adversary impossible: another process with the same UID can rename or replace paths between separate syscalls or after readback. The lease prevents cooperative concurrent attempts, not malicious same-UID tampering or graph authorization. Independent post-stage SSH readback is required before any later gate consumes the file.

The remote output is an observation, not a cryptographically authenticated owner ACK. G279 graph `--run` stays NO_GO pending the separate original-octos owner provenance, v7 EVO19 readback, seccomp/descendant proof and generated-action gates.
