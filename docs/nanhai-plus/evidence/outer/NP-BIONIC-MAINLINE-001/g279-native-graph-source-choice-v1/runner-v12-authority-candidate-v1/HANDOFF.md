# G279 v12 native graph authority candidate — static only

Decision: `GO_STATIC_REVIEW_ONLY`. This is a new generation copied from the frozen v11 runner; v11 remains unchanged. No graph, target compile, device, container, namespace or remote write was performed by this candidate.

The v11 `--run` hard rc3 is removed. v12 first verifies a detached OpenSSH signature over the **exact owner ACK bytes** with a pinned Ed25519 public key, principal `nanhai-plus-original-owner` and namespace `nanhai-plus-g279-graph-v12`. Signature failure returns rc3 before the release parser or any graph output directory. The release parser then binds the signed ACK SHA to the runner, outer release, nonce/session and EVO19 active-environment gate; the signature is checked again immediately before the graph command. Existing v11 source, graph, trace and output guards are inherited but renamed into v12 one-shot paths. The public key is the currently listed Mac ssh-agent key; its private half was not read, copied or staged. Read-only gz02 inspection found no forwarded SSH_AUTH_SOCK or reachable agent there. The pinned key prevents the gz02 staging UID from minting an ACK signature through the staged same-UID JSON files.

**Important limitation:** the existing Mac ssh-agent key is available to other same-user Mac processes, including the outer coordinator. It does not by itself prove the original Herdr owner session signed. Release additionally requires independent verification of the original `nanhai-plus/octos-inner` JSONL tool command, tool rc0, exact ACK and signature SHA, session/claim continuity and fresh nonce. For strict cryptographic separation between outer and owner, generate a dedicated signer under a distinct principal/hardware key and revise the pinned key in a further reviewed runner generation. This candidate must not be interpreted as that stronger separation. There is no actual owner graph ACK, signature, v12-specific EVO19 gate, v12 outer release, remote runner staging/readback, process-tree trial or one-shot release yet. The signature is an execution boundary against remote self-attestation, not a substitute for those missing gates.

Local checks: `python3 -B static_fixtures.py` rc0 with valid fixture, altered ACK, wrong namespace, wrong public key and absent signature; `--static-check` rc0. A local `--run` denied before graph because there is no owner signature. Local fixture keys are generated only in a temporary directory, are not an authority key and are not copied into the candidate. No remote execution occurred. A later independent peer should inspect full v11-to-v12 diff and run the fixtures on Linux; the Mac fixture fallback uses `/dev/fd`, while gz02 uses Linux `memfd_create` and `/proc/self/fd`.

Before release: freeze the v12 SHA, stage/read back exact bytes through a separate reviewed one-shot packet, make a v12 EVO19 gate with actual active env and 11 remote rows, publish an outer release with a new nonce and exact v12 argv/SHA, deliver a bounded request to the **original** owner, obtain and independently witness its graph-only ACK and `ssh-keygen -Y sign -n nanhai-plus-g279-graph-v12` command over those exact ACK bytes, independently review the signed remote packet, and only then issue an execution-adjacent release. Never reuse v11 gate/release/ACK. Target compilation is a separate generation.
