# G279 v2c v2 private gz02 route candidate — independent review

This generation addresses the v1 peer `NO_GO_V2C_V1_RELEASE`: v1 retained only hashes and derived booleans for the decisive positive route and SSH authentication. v2 remains **code only**, unreleased, and has no real selected-node, gz02 SSH, device, container, graph, HK01, or global proxy execution.

The selected real node is copied into a separate v2c private 0600 config and renamed to the fixed, credential-free `g279-v2c-selected` alias. A successful candidate run would export the complete Mihomo route line only after strict full-line matching of timestamp, loopback source, `1.95.90.207:58222`, `IPCIDR(1.95.90.207/32)`, `PROXY`, and that alias. It exports the exact line and SHA, and `replay_positive_event` must reconstruct the same event after the private log is deleted. The real selected node label and credential fields never appear in this event.

The SSH identity proof exports only three complete safe witnesses: the fixed ED25519 host-key fingerprint line, the exact `Authenticated to 1.95.90.207 (via proxy) using "publickey".` line, and numeric `id -u` stdout. `replay_ssh_proof` reparses those bytes and independently checks the retained UID, fingerprint, auth method, and line hashes. The full debug stream is not exported; its SHA remains context metadata rather than a replayable witness. If the real SSH client emits a different authentication line, this oracle fails closed and requires a new reviewed candidate. No real SSH handshake has been made.

The no-credential [loopback format probe](LOOPBACK-FORMAT-PROBE.json) ran the exact pinned Mihomo binary with a private fake SOCKS node listening only on `127.0.0.1`. The fake node received the target tuple but did not dial it. One positive line matched the v2 parser byte for byte; its full safe line and SHA are in the probe receipt. The probe used no selected real node, SSH, or gz02 connection. It cleaned its process and temporary directory. Offline [fixtures](FIXTURE.json) also cover round-trip and altered action, rule, target, alias, host key, authentication, and UID failures.

The v2 runner preserves exact v2a/v2b receipt and binary locks, fixed local `ssh -G` configuration, read-only remote `LC_ALL=C /usr/bin/id -u`, separate private directory and one-shot START/TERMINAL gate. A future run requires a new `peer-review-v2/REVIEW.json` GO and root `root-release-v2/ROOT-RELEASE.json` binding exact hashes. Both are absent. The v1 rejected candidate and nonce are never replayed.

Remaining boundary: SSH witness formatting is fixture-proven but not real-handshake-proven. The existing runner places START before several no-credential prechecks; a separate future preflight receipt could reduce consumed nonces, but this generation does not claim that improvement. Device or APK outcomes are unrelated.
