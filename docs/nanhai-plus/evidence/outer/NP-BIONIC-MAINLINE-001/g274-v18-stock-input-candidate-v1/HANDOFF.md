# G274/v18 stock graph input candidate

This is a frozen **input candidate**, not an executable graph release. It uses the accepted nine exact `android-16.0.0_r4` repository identities and the frozen G273/v17b source and SDK contracts. The read-only gate is:

`python3 scripts/nanhai_plus_env.py --run python3 -B docs/nanhai-plus/evidence/outer/NP-BIONIC-MAINLINE-001/g274-v18-stock-input-candidate-v1/verify_input.py`

The gate independently reads every one of the 85,499 tracked entries in the nine roots (1,875,247,905 logical bytes), checks mode, size, SHA-256, Git blob, and complete path inventory, then checks all four old/new overlaps by exact content and all 13 original link payloads. Twelve links resolve to qualified stock paths. `frameworks/native/include/private/binder` remains the original R4 symlink to absent `frameworks/native/libs/binder/include/private/binder`; preserve it as dangling. It is a source-view caveat, not an observed graph failure. Four overlaps are identical; zero different-byte overlaps are admitted. No source tree, shared index, old candidate, graph output, or device is changed.

The nine whole-root stock binds in `INPUT-CANDIDATE.json` extend G273/v17b in listed order. They are **stock-phase-only** read-only binds to `/src/...`; the materialization phase must leave them absent while creating the private source volume's mountpoints. The existing v17b materializer's `ROOT_OVERLAP` permits only two old selected-file overlaps. A v18 integration must add these four exact paths to that policy: `frameworks/base/data/fonts/fonts.mk`, `frameworks/base/data/keyboards/keyboards.mk`, `frameworks/base/data/sounds/AllAudio.mk`, and `hardware/interfaces/configstore/1.1/default/surfaceflinger.mk`. The authoritative SHA-256, mode and byte count for each are in `INPUT-CANDIDATE.json`. Verify their byte/mode/Git blob identity before and after the bind, and reject any other overlap. It must extend the frozen G273 manifest/plan prefix and preserve the original stock shell verbatim; it must not edit BP files, stub missing modules, or remove the dangling link.

The one-shot execution contract, **after** independent input and integrated executor/materializer review, root review, fresh original `nanhai-plus/octos-inner` owner ACK, and a new root seal, is: (1) pre-guard the frozen v17b full source view, all nine new roots, and the 17,924-entry exact SDK; (2) create fresh private source, OUT, and TMP volumes with original claim/nonce ownership and offline fixed Linux image; (3) materialize the original source volume and exact selected bytes, verify the four overlays and 13 links, then mount 29 old plus nine new roots and SDK read-only; (4) inspect all Linux mount sources, destination identities, and `RW=false`, run the unchanged stock `soong_ui` graph once with the fixed 600-second bound, capture actual stdout/return code/first wall; (5) export OUT/TMP evidence, clean only the newly owned resources, then re-run all source and SDK guards and require pre/post equality. Never replay G273's terminal package or infer a graph PASS from this candidate.

The fixed resource envelope is `--pull=never`, `--network=none`, `--read-only`, `--cap-drop=ALL`, no new host service, six host CPUs, three fresh private volumes, `GOPROXY=off`, and the pinned image in `INPUT-CANDIDATE.json`. The prospective command may only be issued from a separately sealed v18 executor through the original owner. This directory deliberately contains no Docker runner or Herdr dispatch and grants no execution authorization.

The SDK and v17b source manifests are hash-bound here; the candidate gate does **not** reread their 6.25 GB + legacy source contents. Those complete pre/post guards remain mandatory in the eventual one-shot executor. The next reviewer should validate that the new four-overlap policy, nine binds, 13-link semantics, full source/SDK guards, and Linux RO mount checks are implemented before requesting the original owner's ACK. Soong transitive graph, ARM64 target compilation, App startup, devices, and Bionic 89-tool completion remain unproven.
