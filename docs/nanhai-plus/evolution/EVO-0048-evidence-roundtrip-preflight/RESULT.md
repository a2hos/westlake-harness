# EVO48 — 候选执行前的证据往返检验

范围仅为本轮四组结果：G279 v2b v1、v2、v3 各一次 NO_GO，以及 Steam Chat 官方原包与黑盒资格收据。v1 的 SOCKS 负例会把截断/普通故障误认作规则拒绝；v2 修复语义后只留下不可复核的事件 SHA；v3 导出规范化事件，但原日志行 SHA 仍因缺时间戳而无法从成功终态复算。Steam Chat 的已保存 APK 则可以从原字节重算 SHA，作为对照。该差别是证据可复算性问题，与 EVO46 的契约时序、EVO47 的人力 ROI 分配不同。

**唯一改进**：在候选准入前做一次“决定性证据往返”小试验。列出每个将用于 GO 的事实、执行后实际保留的最小无敏感见证，以及独立 reviewer 的复算式；用无凭据 fixture 将见证序列化、删除模拟私有原件后重算。任一决定性 SHA 无法从保留见证复算，候选停在 code-only，不发真实 one-shot release。对 G279 v2b，下一代只需保留经整行严格白名单校验的安全路由行，或保留时间戳与精确字节重构规则；完整 debug 流继续私有并按清理门删除。

本目录 `pilot.py` 只读重算了 v3 mock 原行 SHA 与规范化事件 SHA，均通过；模拟真实终态仅剩规范化事件时，原行因缺时间戳无法重构。它还从 Steam Chat 原 APK 重算了 intake SHA，作为可复算对照。具体输入 SHA 和布尔结果见 `PROCESS.json`。试验不读取真实节点凭据、不启动代理/SSH/设备，不改计数。该方法目前只在这四组证据上试水，**不自动推广**；下一次只用 v2b 新代的无凭据 mock 与预期终态检验是否同时复算两种 SHA，成功且独审后再考虑纳入候选准入模板。
