# EVO49 — 缩小一次性试验的可观测阶梯

本次仅比较四组已发生结果：v2b v4 的本地 TEST-NET-3 REJECT 局部事实（外层 rc2）、Steam Chat 四阶段主机静态、DuckDuckGo 官方原包及同 tag 白盒输入、v2c v1 code-only NO_GO。精确收据 SHA 与阶段行号见 `PROCESS.json`。没有把静态、原包或资格算成启动。

**唯一小改进**：把 v2c 复合试验拆成“无凭据本地预检收据”和“另行签发的一次性私有路由加只读 SSH”。先用无凭据阶段核二进制、Seatbelt fork 拒绝、源码、当前控制器节点、端口，然后才消费真实路由 nonce；后半段的 SSH 与路由各留独立阶段终态。它针对的是试验粒度与 nonce 消耗，区别于 EVO46 的契约时序、EVO47 的人力分配、EVO48 的证据往返。

小范围只读试验核了冻结 v2c runner：`START` 在 379 行，随后五个无凭据失败门位于 380–396 行，私有配置写入到 405 行才发生，真实 SSH 位于 351 行的实例路径。若这些预检失败，当前设计会先消费一次性 `START`。这只支持在下一代尝试拆分，不证明真实路由可行。验证标准是任一无凭据负例留下明确预检失败且不消耗真实路由 nonce；后段必须绑定新鲜预检收据，否则拒绝。

目前 **不推广、不 release**。v2c v1 的私有正向路由与 SSH 认证见证仍未满足 EVO48 可复算门，拆分不能替代这个修复。未启动代理、连接 SSH、访问设备或运行容器，也未改总账。
