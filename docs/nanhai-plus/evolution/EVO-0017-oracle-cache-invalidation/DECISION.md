# EVO17 — G274 oracle allowlist identity on reuse

Scope: OH7.0.0.39 / Android 16.0.0_r4 / ARM64, G274/v18 stock graph *candidate* only. This is a bounded read-only reflection, not release, host graph, APK, or device evidence.

Problem: G274's first full executor reused the G273 29-root output oracle. The independent review and root block showed that a successful graph containing the nine admitted R4 roots would be falsely rejected. The v2 candidate added exact manifest-backed allowed paths; this reflection checked whether the same process could reuse them after input identity changed.

Primary lens: transfer learning from content-addressed cache validity. Source domain: a cache hit is valid only under its complete input identity. Target domain: a source-path oracle reused during candidate validation and output review. Shared invariant: permitted paths derive from pinned manifests. Critical mismatch: a process-local set does not itself recheck the files from which it was derived.

Observation: the initial v2 `oracle_policy.py` returned module-global `_allowed` before calling `extension.candidate()` or hashing admitted manifests. An isolated stub injected `ValueError('identity drift injected')`: with a populated cache the call returned `['sentinel/Android.bp']`; with an empty cache it raised. This first interactive observation was not saved with a source SHA or wall-clock timestamp, so it is a transient finding, not a reproducible pinned failure receipt. The independent v2 author then removed that early cache path while this reflection was running. The frozen local [pilot](pilot.py) against policy SHA `5b2676f41cded0e2828bb9e61a13529accf76440685a3714efa87515144c8c64` returns rc0: both a populated-sentinel case and the uncached negative control raise `candidate identity changed`; [result](RESULT.json) records the exact policy SHA. Neither trial touched the source pool, Docker, or a device.

Discarded action: accept a prior allowed-path set merely because an earlier invocation validated it. Its observed failure is the first stub result; its cause is a cache hit before input identity checking. Replacement: recompute the exact allowed set from the SHA-bound admitted manifest at each oracle invocation, or use a complete input-content key with rehash on each hit. This removes the stale-allowlist retry risk while preserving exact path rejection. Applicability is limited to the candidate oracle and manifests; no graph success is inferred.

One local improvement verified: the v2 policy now revalidates candidate identity on repeated invocation. Causal chain: inherited oracle missed nine roots -> exact-set extension introduced reuse risk -> reject unkeyed cached set -> avoid stale acceptance / needless graph rerun -> injected changed-candidate case is rejected even after a prior set exists. Positive real-manifest and negative unlisted-path tests, independent review, original owner ACK, root seal, and actual Linux graph remain the next evidence. Stop if any admitted input changes or a negative path is accepted. Do not promote this pilot as a new tool or a passed Bionic item.

State: observation and isolated verification only. The current policy file can still change until the v2 candidate is frozen and independently reviewed; rerun the same pilot against its final SHA. Candidate implementation/release decisions remain with root; no global method export is approved by this record.
