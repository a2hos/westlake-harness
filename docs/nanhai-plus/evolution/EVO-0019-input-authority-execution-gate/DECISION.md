# EVO-0019 — bind remote input bytes before execution

EVO18's read-only type cohort grouped all 181 G275 unrecognized-type diagnostics and led to the exact R4 `system/tools/hidl` and `system/apex` source intake. G276 did not test whether this removed the graph errors: its actual attempt stopped at `ValueError: init mount drift` before any stock graph step. Thus the earlier candidate improved source discovery, but graph cost or correctness improvement remains unproven.

The next four observations expose a narrower gate. G276 failed because a delegated wrapper retained an older leaf binding despite a current candidate. G278 built a native Linux x86-64 `soong_ui` with rc0 in an isolated worktree/output; this proves the host tool, not a target graph. G280's archive.mozilla.org APK has successful ZIP, badging and signature preflight, yet its bytes differ from the historical Firefox registry hash, so it remains a new variant candidate. G279 delivered three read-only inputs to gz02 with remote rc0 and independently matched SHA, size and 0444 mode; the peer accepted only those files. Its outer command rc0 was reported by the owner but is not encoded separately in `STAGING.json`. These results show why source authority, packet delivery and execution identity must meet at the same gate.

**One small improvement candidate:** before releasing any remote native graph command, use one fail-closed pre-execution check that records and compares the authoritative `local_env.md` binding digest, exact runner/wrapper SHA, each remote control input SHA/size/mode, and the intended remote argv/interpreter; record both SSH outer rc and remote rc in the same immutable gate receipt. A mismatch or missing field stops before graph invocation. The check should re-read remote bytes immediately before dispatch, since G279's successful staging receipt alone does not prove later state. This is a proposal, not a released runner or a new build result.

The read-only pilot in `PILOT.json` returned rc0: it hashed seven original receipts and asserted G276 terminal error, G278 tool rc0, G279 three-file remote rc0 plus actual-peer digest link, G280 candidate-only status, and EVO18's 181 grouped diagnostics. It did not SSH, graph, access a device, or change canonical counters. Falsify the improvement if a later gated run with all input hashes and argv matching still fails from an unbound delegated wrapper; then extend the gate to that wrapper rather than treating the hashes as sufficient. Also test that changing one remote byte or a declared binding causes the pre-execution check to reject before launch.

No graph pass, target compile, APK runtime, device result, time saved, or global process promotion is claimed. The original Firefox SHA mismatch and G276 terminal failure remain intact.
