# EVO-0015: module-definition owner probe

Problem: G271 graph ended at six unknown module types; after supplying exact R4 AIDL/XSDC plugin owners, G272 spent another full graph pass and ended at five undefined module names. The decision is whether a cheap source/view owner probe can identify the next missing source owners before repeating a full graph, without claiming graph closure.

Primary lens: `_rethink_other_path`. Current route is one full Soong graph generation per newly exposed dependency wall. Alternative A is a targeted lexical owner probe against the exact AOSP16 R4 shared source pool and the *actual* G272 stock command bind mounts. Alternative B is Soong's authoritative graph itself; it understands namespaces, conditional modules, plugins, and generated definitions but costs the full container round. The local probe is chosen only to prepare the next isolated source candidate; authoritative acceptance remains a new graph.

Observation: `G272-REVIEW.json` records rc2 and five undefined names after 240 Soong bootstrap steps. `TRIAL.json` shows one `name:` definition for each: platform_testing/tradefed-error-prone, Car/aconfig, system-extras/simpleperf, lint_checks/common, and Connectivity/tests/common. None of those owner roots is a source bind in G272 `stock-COMMAND.json`. This exactly predicts five candidate owner gaps; it does not establish that mounting them will produce graph PASS. `CONTROLS.json` shows mounted `aidl_defaults` is *not* flagged absent, while an invented name with zero definitions is classified unknown rather than falsely attributed. Probe rc0, 0.97 s; controls rc0, 0.38 s. Read-only, no Docker, graph, device, or Herdr actions.

Inference: G272's repeated full-graph cost came partly from source-provider closure being discovered only after generation. A narrowly keyed check (module name + exact R4 source pool + exact stock-command bind view) can eliminate one avoidable discovery graph when the owner has a simple literal `name:` declaration. Input identity is the immutable G272 command receipt plus pool version; re-run when any candidate mounts or source identities change. Failure semantics: zero matches, duplicates, unsupported syntax, or timeout remain `unknown` and never become permission to suppress a graph.

Discarded action: replaying G272 unchanged or treating the previous AIDL/XSDC plugin repair as full source closure. Source anchor: G272 root review and its stock command; observed failure: five different undefined names; mechanism: missing provider roots; replacement: inspect owners and source-view mapping before submitting G273. This removes a potential redundant graph attempt, not compilation or device validation.

Limitations: a lexical `name:` match is not a Soong parser. Namespace visibility, generated modules, selected product variables, baseline volume contents, version integrity, symlink targets, and transitive owner dependencies require separate gates. One positive and one negative control do not establish population-wide precision or recall. This is a local, unpromoted candidate. Next evidence: independent source/command identity review, then one isolated G273 candidate and a single sealed graph; stop if a target name has no unique exact-version owner or the mount plan changes.
