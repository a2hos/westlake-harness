# EVO50 — 私有日志清理前的最小失败诊断

本轮只看四组结果：DuckDuckGo 静态与白盒输入、Proton VPN 原包/静态/白盒输入、G279 v2c v2 代码候选 GO、v2c v2 one-shot rc2 且 SSH 子阶段未知。精确收据和 SHA 见 `PROCESS.json`。前两组保留各自静态/输入边界；触发本次改进的是最后一组：TERMINAL 只记 `InstanceFailure` 和一次本地 SSH 启动，私有日志删除后无法区分传输超时、认证失败、远端命令失败或正向路由解析失败。

**唯一改进**：失败路径在清理前导出固定白名单诊断元组：最后完成的阶段、失败类别、子进程 rc 或空值、是否超时、两路流的有界字节数。禁止任意异常消息、原始 stdout/stderr、节点名和凭据出现在公开收据。这只帮助定位失败，不替代 EVO48 所要求的成功见证，也不改变 EVO49 的 nonce 阶梯。

`pilot.py` 对真实 v2c 终态和三个无凭据合成失败做了 8 项检查：三个失败阶段保持可区分，任意私有标签/自由文本类别/无界流大小被拒绝，原 v2c 子阶段仍如实为 UNKNOWN。`PILOT.json` 给出精确数据。下一代只在隔离候选里试：对各阶段注入无凭据故障，核终态能区分故障且不会泄露敏感文本；任一不满足即否决。当前 **不推广**，未改生产运行器、总账、设备或容器。
