# 南海 plus ExecPlan — Bionic 主线

本计划保留原 21 个 step ID 和历史收据；B0–B7 是当前架构里程碑，不改分母、不把文档完成报成工程完成。遵循 [Agent Spec](AGENT-SPEC.md)、[GOAL](GOAL.md)、[外环 Prompt](OUTER-PROMPT.md)。

当前最高优先级约束：容器只可作 `dev-only` 开发辅助，不能成为系统架构或交付依赖。G276 图前失败及 G277/v21 容器候选保留为历史审计；可以用容器做局部扫描、依赖准备或测试夹具，但正式构图、ARM64 目标产物、HelloWorld 安装/冷启动/上屏必须走可审计原生宿主路径，开发容器结果不能迁入交付 PASS。

每一执行包包含 target/revision、来源/SHA、写集、实际命令、超时、资源 owner、恢复方法、消费者 oracle 和幂等键。原 owner ACK 后执行，首失败保留并停止本包后续依赖动作，其他独立任务继续。新修复另起版本，不改封存包。

外环沿原 30 秒脚本观察和 outbox 派发；每 3–5 分钟及 peer 返回后语义对账。Kimi/GLM/Codex 依能力和可用槽承接有界包，外环独立验收。反思仍按 3–4 组实际结果、120 秒、最多一项改进，准备与控制切换不计数。


## 当前活动范围扩展：登记全集与 200 APK 启动

用户当前活动目标为：学习 westlake-harness 方法，使用本机 OH7/AOSP16/ARM64 与 App 单 Bionic 架构，真实启动至少 200 个不同原包应用，其中至少 100 个经核验的海外主流黑盒应用。上游登记全集保留并逐项复现；超过 200 个仍继续全集处置，原 HelloWorld、89 项适用工具、10/30 APK 与 API/AIDL 契约目标保留。完整执行规则见 [PORTFOLIO-GOAL](PORTFOLIO-GOAL.md)。

登记、获取、扫描、尝试与成功分列。启动数只计本代原包真正冷启动进入其真实 Activity 生命周期、具有 APK/runtime 哈希、进程身份和运行日志的独审结果；安装、PID、宿主构建与历史通过不计入。上屏、输入与恢复分别验收。200 次尝试不能替代 200 个启动成功。

原 goal/session/claim、累计预算、设备权限和唯一调度器保持。只有符合最新无容器约束的当前执行包可以沿冻结契约执行；历史容器包和 G277/v21 候选已撤销。范围扩展须通过原 owner 的有界元数据回读同步，未取得该收据前不能宣称原生 goal 已同步。
