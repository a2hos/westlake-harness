# 无容器架构修订

用户最新决定：南海 plus 全过程杜绝容器。Docker、Podman、OCI 镜像和容器内进程均不用于构建、扫描、测试、桥接或 App 运行；原生宿主上的 namespace/chroot/nsjail 类隔离也暂不作为替代路径。只有普通原生进程、项目独立输出目录和只读精确版本源码输入可进入新执行包。

此前容器出现在 **宿主构图**，不是 App 内桥接：本机为 macOS，而已准入的 `soong_ui` 是 Linux x86_64 ELF/glibc，旧执行器用 Linux/amd64 镜像运行 AOSP16 R4 宿主工具并通过只读挂载模拟 stock 源码树。这项工程便利与用户要求的架构边界不一致。G276 在容器初始化校验处失败，也没有产出 Soong 图；G277/v21 沿用同一容器执行器，即使修好路径仍不符合新约束。

处置：G252–G276 容器收据和封包保留为历史证据，不继承为原生宿主构图成功；G277/v21 静态候选撤销，不派发、不封包、不执行。原 `goal_01`、`nanhai-plus/octos-inner`、claim 身份、累计预算、89 项与 200 APK 目标、设备 HOLD 保留。

新路线先确认一台可用的 **原生 Linux x86_64 宿主**及同版源码/工具链，固定源码 commit、工具 ELF、系统 loader、glibc、工作树和输出路径。用本项目独立的源码视图、OUT/TMP/staging，在普通宿主进程中直接运行原版 AOSP 构图命令；不得通过容器命令或镜像代理。先做只读环境与 sandbox 行为核验，再形成新的宿主原生执行器、原 owner ACK、独立审查和一次性图验证。宿主图通过后仍需 ARM64/Bionic 目标编译、安装/服务链、HelloWorld 冷启动与上屏输入闭环。尚无原生宿主图、目标编译或设备通过证据。
